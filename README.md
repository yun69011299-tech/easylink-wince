# EasyLink — Windows CE 车机手机投屏方案

在**仅有 USB 口的老 WinCE 车机**上实现类 CarLife 的手机投屏体验：手机屏幕镜像到车机、车机触屏反向操控手机。本项目**自研两端**（车机端 + 手机端 + 私有协议），彻底摆脱原亿连/EasyConnected 方案对 ADB 授权与 127.0.0.1 回环隧道的依赖。

## 背景

原亿连方案（逆向分析见 `dex_out.txt`）在实际使用中连接不可靠，根因：

- 手机端仅监听 `127.0.0.1:40690`，车机必须通过 **ADB host + `adb forward`** 才能打通（USB 调试授权弹窗、驱动缺失任一环节失败即"无反应"）
- 协议为私有 EC47 格式，无音频通道
- 手机端官方 App 与第三方重制版协议不完全兼容

本项目改为：**车机端主动实现连接通道**，协议完全自主，两端代码均在本仓库。

## 架构

```
┌─────────────┐   USB 物理连接    ┌──────────────────────┐
│  Android 手机 │◄───────────────►│  WinCE 车机 (ARM)     │
│  录屏+编码    │  自定义 TCP/串流   │  EasyLink 接收端.exe  │
│  触摸注入     │  EC47 协议        │  解码显示+触摸回传     │
└─────────────┘                   └──────────────────────┘
```

## 目录结构

| 路径 | 内容 |
|------|------|
| `car/src/` | 车机端源码（C，Win32/CE API）：`main.c` 界面与消息循环、`probe.c` 系统/驱动探测、`log.c` 环形日志+SD卡落盘 |
| `car/build.sh` | 一键构建（WSL 内编译，产出 ARM/CE exe） |
| `car/dist/` | 发布产物（按版本命名） |
| `dex_out.txt` | 手机端 APK 完整反汇编（EC47 协议原始依据，含全部字符串与调用链） |
| `dexdump.js` | 自制 dex 反汇编工具（`node dexdump.js`，需先解包 APK 到 `apk_out/`） |
| `*.apk.1.1` | 逆向分析用的原始手机端 APK |
| `AGENTS.md` | **开发交接指南**（环境重建、构建命令、已知坑、路线图） |

## 快速开始（车机端构建）

```powershell
# 需先按 AGENTS.md 完成一次性环境安装（工具全部在 D:\LGprogram\wince）
wsl -d Ubuntu -u root -- bash /mnt/d/LGramfiles/trae/car/build.sh
# 产物: car/dist/EasyLink-v*.exe → 拷到 SD 卡 → 车机运行 → 回传 \SDMMC\easylink_probe.log
```
